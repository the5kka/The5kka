# Codex 작업 기준

1. 빠르게 만드는 것보다 먼저 검토하고, 실행 테스트까지 한 뒤 사용자에게 전달한다.
   - 실행 파일은 만들기만 하지 않는다.
   - 최소한 실행 가능 여부, 기본 로딩, 핵심 기능 1회 동작을 확인한다.
   - GUI 프로그램은 실제 화면이 뜨는지 확인한다. `--self-test`만 통과했다고 전달하지 않는다.
   - 오류 가능성이 보이면 먼저 사용자에게 "테스트 전 버전"이라고 분명히 말한다.

2. 수정 요청은 기본 기능과 기존 양식을 건드리지 않는 것을 원칙으로 한다.
   - 사용자가 요청한 부분만 최소 범위로 수정한다.
   - 원래 있던 문구, 칸, 양식, 규칙, 출력 구조는 임의로 삭제하거나 변경하지 않는다.
   - 필요해서 바꿔야 할 경우 먼저 이유를 설명하고 확인받는다.

3. 현장 배포 폴더는 지저분하게 만들지 않는다.
   - 바깥에는 사용자가 볼 최종 실행 파일과 필요한 엑셀만 둔다.
   - 개발 파일, 백업, 테스트 결과물은 숨김 보관 폴더에 둔다.

4. 엑셀 기반 프로그램은 먼저 엑셀 내부 규칙을 확인한다.
   - 시트 구조, 병합 셀, 인쇄 영역, 행/열 크기, 이미지 앵커, 수식, 설정표를 먼저 확인한다.
   - 원본 양식이 있으면 새로 그리지 말고 원본 양식을 유지하는 방식을 우선한다.

5. 현장 프로그램은 사용 방식이 기존보다 불편해지면 안 된다.
   - 기존에 있던 미리보기, 파일 선택, 프린트 흐름은 유지한다.
   - 사용자가 승인하지 않은 브라우저 UI로 바꾸지 않는다.
   - 화면에 표시되는 불필요한 문구(예: 구현 언어명, DONE 같은 개발자 상태값)는 넣지 않는다.
   - 사용자가 엑셀을 하나씩 열어 확인해야 하는 방식은 최종 사용 방식으로 전달하지 않는다.
