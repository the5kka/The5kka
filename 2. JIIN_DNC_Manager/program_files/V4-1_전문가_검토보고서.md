# JIIN DNC Manager V4-1 전문가 검토보고서

- 검토일: 2026-07-11
- 기준 버전: JIIN DNC Manager V4
- 검토/개선 버전: JIIN DNC Manager V4-1
- 최우선 목표: 현장 오조작, 잘못된 DNC 조건 전송, 작업일보/DB 손상, 완료 오판 방지

## 1. 최종 판단

V4 원본은 수정하지 않고 V4-1을 별도 실행 파일, 별도 소스, 별도 데이터 폴더로 만들었다. V4-1은 기존 기능을 유지하면서 실패 시 작업을 중지하는 방향으로 강화했다.

코드 회귀시험, 실제 작업일보 사본 저장/재개방 시험, SQLite 무결성 시험, PyInstaller EXE 기동시험, V3/V4 동시 실행 차단 시험은 통과했다. 다만 실제 DNC 설비가 파일을 읽는 시간, 현장 네트워크 권한, 2대 PC 동시 작업일보 반영, 듀얼 모니터/원격 데스크톱 팝업은 이 개발 PC 한 대의 자동시험만으로 완전 보증할 수 없다. 따라서 이 보고서의 현장 합격시험을 통과한 뒤 V4-1을 본 적용해야 한다.

현재 V4-1 설정에는 TLB/KCC HDI 조건 시트 경로와 일부 DNC 원본 경로가 비어 있다. 이것은 오류가 아니라 V4 설정을 그대로 분리한 결과이며, 해당 공정은 경로를 설정하기 전에는 안전하게 실행이 차단된다.

## 4. 실제 작업일보 구조 확인 결과

검토 파일: `C:/Users/오국진/Desktop/타사 DNC 작업일보.xlsm`

| 시트 | 헤더 행 | DNC_LOG_ID 열 | 확인 결과 |
|---|---:|---:|---|
| TLB | 2행 | AE(31) | 매핑 일치 |
| KCC PKG | 6행 | AE(31) | 2행 입력/수식 영역과 6행 실제 헤더를 구분함 |
| KCC HDI | 2행 | AE(31) | 매핑 일치 |
| 심텍 HDI | 2행 | AG(33) | 사용자 지정 AG열과 일치 |

확인 사항:

1. 실제 XLSM을 임시 사본으로 저장한 뒤 ZIP 구조 검사와 `openpyxl` 재개방에 성공했다.
2. XLSM은 `keep_vba=True`로 VBA를 보존한다.
3. 외부 링크는 `keep_links=False`로 저장해 기존의 깨진 외부 링크 복구 경고 재발 가능성을 줄였다.
4. 작업시간은 날짜가 아닌 시간 값과 시간 표시 형식을 사용한다.
5. 신규 검증도 별도 임의 시트가 아니라 해당 공정 DB/작업일보에 `dnc_type`으로 구분되어 저장된다.
6. 작업일보가 Excel에서 열려 저장할 수 없으면 DB 이력은 미반영 상태로 남고, 다음 반영에서 다시 시도한다.

## 5. 정상 DNC 처리 흐름

1. 공통 입력과 LOT 입력을 읽는다.
2. 근무/작업자/날짜를 작업 시작 시점의 스냅샷으로 고정한다.
3. 필수 입력, 숫자, LOT 2 사용 여부, 동일 LOT, 조건 일치 여부를 검사한다.
4. 조건 마스터 또는 조건 시트에서 조건/지그를 조회한다.
5. 조건 파일명과 정확히 같은 `.txt`가 한 개만 있는지 검사한다.
6. 축, Stack, 매수로 1회 용량과 총 사이클을 계산한다.
7. DB에 진행 중 이력을 먼저 저장한다.
8. 전송 폴더의 기존 TXT를 기록 후 정리한다.
9. DNC 파일을 숨은 임시 파일로 복사한다.
10. 원본/복사본 크기와 SHA-256을 비교한다.
11. 검증 완료된 파일만 최종 TXT 이름으로 원자 교체한다.
12. 설정된 시간 동안 설비가 읽도록 기다린 후 TXT 삭제를 최대 30회 재시도한다.
13. 삭제 성공을 확인한 뒤에만 초품/Burr 확인, 사이클 차감, 완료 처리를 수행한다.
14. 모든 사이클 완료 후 DB를 완료 상태로 바꾸고 작업일보를 반영한다.

핵심 원칙은 `복사했다고 완료가 아니며, 전송 파일 삭제 성공과 품질 확인까지 끝나야 완료`이다.

## 6. 심텍 HDI 신규 검증 흐름

1. STEP, 차수, 관리번호, LOT, 매수, OMS 조건, 추가가공을 검사한다.
2. OMS 문자열에서 사이즈, Shift, 지그 Y값, 차수를 파싱한다.
3. 화면 차수와 `후가공(n차)`가 다르면 실행을 차단한다.
4. 추가가공 `없음`은 DB/파일명 조합에서는 빈 값으로 취급한다.
5. 생성 조건명과 정확히 같은 TXT가 한 개만 있을 때만 실행 버튼이 활성화된다.
6. 조장명은 공통 작업자와 별도인 강제 팝업에서 받는다.
7. 하부 Pin 축과 Stack으로 1회 최대 용량을 계산한다.
8. 검증 매수는 작업자가 직접 입력하며 0은 더미 검증이다.
9. 0매 검증은 실제 제품 수량을 차감하지 않는다.
10. 일부 매수만 검증하면 검증 종료 후 남은 매수/사이클을 본 심텍 HDI 화면으로 인계한다.
11. 하부 Pin 축과 초품 축이 다르면 완료할 수 없다.
12. `초도품 및 4면 Burr 이상 없음`일 때만 조건 마스터에 등록한다.
13. NG이면 `Burr/초도품 이상`으로 저장하고 조건명에 검증 NG 표시를 남기며 마스터에 등록하지 않는다.

예: 전체 96매, 1회 48매, 신규 검증 48매이면 신규 검증 후 본 화면에 48매/1사이클이 남는다. 신규 검증 0매이면 96매/2사이클이 그대로 남는다.

## 7. P0: 불량/오작동 직결 위험과 조치

### 7.1 DNC 원본 경로가 없는데 빈 폴더를 만드는 위험

- 이전 위험: 경로 오타를 정상 빈 폴더로 오인할 수 있음.
- V4-1: 원본/전송 경로가 없으면 즉시 중지하고 폴더를 자동 생성하지 않음.
- 효과: 잘못된 경로에서 조건 없음으로 오판하는 일을 방지.

### 7.2 비슷한 파일명을 잘못 복사하는 위험

- 이전 위험: 조건명 일부가 같은 REV/OLD 파일을 잘못 선택할 가능성.
- V4-1: 확장자 `.txt`, 파일 stem 완전일치, 대소문자 정규화 기준으로 조회.
- 같은 이름이 2개 이상이면 목록을 보여주고 실행 차단.

### 7.3 복사 도중 설비가 불완전 파일을 읽는 위험

- V4-1: `.jiin_part` 임시 파일로 복사 후 크기와 SHA-256 검증.
- 검증 성공 후 `os.replace`로 최종 TXT 이름을 한 번에 노출.
- 복사 실패 시 임시 파일을 정리하고 최종 파일을 만들지 않음.

### 7.4 DNC TXT 삭제 실패인데 완료되는 위험

- V4-1: TLB, KCC PKG, KCC HDI, 심텍 HDI 일반 DNC, 심텍 HDI 신규 검증 전부 삭제 결과를 기다림.
- 최대 30회 재시도 후에도 남아 있으면 빨간 경고, `다음 작업 진행 금지`, DB 미완료 유지.
- 삭제 실패 시 초품/Burr 팝업, 사이클 차감, 완료 저장, 작업일보 반영을 실행하지 않음.

### 7.5 동일 LOT/서로 다른 조건을 2LOT로 함께 실행하는 위험

- 동일 LOT No는 일반 DNC와 신규 검증 모두 차단.
- 심텍 HDI 신규 2LOT는 조건, 지그, 추가가공이 모두 같아야 함.
- KCC PKG 신규 2LOT는 조건/지그가 같고 동일 작업이어야 함.
- TLB/KCC HDI는 조회된 공정/조건 일치 확인 후 진행.

### 7.6 TLB와 KCC HDI 조건 시트 혼입 위험

- 동일 조건 시트를 사용할 수 있지만 A열 공정 값을 필수 필터로 사용.
- TLB 화면에서는 TLB 행만, KCC HDI 화면에서는 KCC 행만 조회.
- 한쪽에서 조건 시트를 바꾸면 공통 설정을 통해 다른 쪽도 같은 파일로 동기화.

### 7.7 근무 전환이 진행 작업 중간에 끼어드는 위험

- 작업 시작 시 공통 정보를 복사해 해당 작업이 끝날 때까지 사용.
- 08:30/20:30에 DNC가 진행 중이면 근무 전환을 예약만 함.
- DNC 완료/실패 처리로 실행 잠금이 풀린 뒤 작업자 초기화와 근무 전환 적용.

### 7.8 Burr 문구 불일치로 Excel 빨간 표시가 빠지는 위험

- 품질 NG 판정을 특정 한 문장만 비교하지 않도록 통합 함수로 변경.
- `Burr 이상`, `Burr 발생`, `Burr/초도품 이상`, 검증 NG를 모두 품질 NG로 판단.
- 신규 검증에는 `이상 없음` 또는 `Burr/초도품 이상`을 명시 저장.

### 7.9 여러 버전 동시 실행 위험

- V4-1은 V4 잠금과 V1~V3 잠금을 동시에 확보.
- V4-1 실행 중 V3/V4 실행 시험에서 두 버전 모두 실행 차단 확인.
- V3/V4가 먼저 실행 중이어도 V4-1은 새로 뜨지 않고 기존 창을 앞으로 올리도록 시도.

## 8. P1: 데이터 손상/간헐 오류/성능 위험과 조치

### 8.1 Tkinter를 작업 스레드에서 직접 호출하는 위험

- 모든 백그라운드 완료/오류 콜백을 메인 UI 큐로 전달.
- 메인 스레드가 일정 주기로 큐를 처리.
- 직접 `after(0, ...)` 호출이 남지 않았는지 정적 시험으로 확인.

### 8.2 팝업이 숨고 EXE가 멈춘 것처럼 보이는 위험

- 팝업은 부모 창의 transient/modal로 연결.
- 생성 직후 한 번 topmost/lift/focus를 적용.
- IME 입력 중 반복 `focus_force()`는 사용하지 않음.
- 이미 열린 관리창을 다시 누르면 새 창을 중복 생성하지 않고 기존 창을 복원.

### 8.3 조장명 한글 마지막 글자 표시/저장 문제

- 실시간 validatecommand/trace/Entry 재작성 없음.
- 조장명은 한글 IME에 더 안정적인 기본 `tk.Text` 한 줄 입력 사용.
- 확인/Enter 후 120ms 기다려 IME 마지막 조합을 커밋한 뒤 한 번만 읽음.
- 입력 중에는 DB/파일 조회를 하지 않음.

### 8.4 심텍 조건 입력 중 화면 버벅임

- 키 입력마다 전체 하위 폴더를 검색하던 경로를 300ms debounce 처리.
- 마지막 입력이 잠시 멈췄을 때만 조건 파싱/파일 검색.
- 정확한 파일이 없거나 중복이면 실행 버튼 비활성화.

### 8.5 설정 JSON 손상

- 임시 파일 쓰기, flush, fsync, JSON 재검증 후 원자 교체.
- 기존 설정 백업 유지.

### 8.6 작업일보 중간 손상

- 원본과 같은 폴더/같은 확장자의 임시 파일로 저장.
- XLSX/XLSM ZIP 검사 후 원본과 원자 교체.
- PC 간 `.lock` 파일을 O_EXCL 방식으로 생성해 동시 저장 방지.
- 10분 이상 된 비정상 잔여 lock만 오래된 lock으로 판단.

### 8.7 DB 스키마 변경 중 손상

- 스키마 변경 전에 SQLite online backup으로 전체 기존 DB와 설정을 별도 폴더에 저장.
- 백업 DB도 `PRAGMA integrity_check` 통과 후 사용.
- V4-1 최초 실행에서 실제 마이그레이션 백업 생성 확인.

### 8.8 DB 장기 누적 성능

- 작업 조회/마스터 동기화용 복합 인덱스 추가.
- WAL 자동 체크포인트 1,000 page 설정.
- KCC 조건 마스터 시작 동기화를 행마다 전체 저장하던 구조에서 한 번의 batch merge/save로 변경.
- 시작 시 기존 DB 전부 `PRAGMA quick_check` 검사. 손상 DB는 조용히 사용하지 않고 시작을 차단.

### 8.9 마스터 오등록 복구

- KCC PKG와 심텍 HDI 조건 마스터에 `선택 조건 마스터 제외` 제공.
- 선택 마스터와 정확히 일치하는 과거 로그 ID 전부에 `master_excluded=1` 기록.
- 마스터에서 삭제해도 작업 이력 원본은 보존.
- 이후 동일 조건을 다시 신규 검증하면 새 로그 ID이므로 정상 재등록 가능.
- 마스터 삭제 실패 시 로그 제외 표시도 원복.

## 10. DB가 오래 쌓였을 때의 판단

### 개선된 부분

- SQLite는 Excel 전체 검색보다 장기 누적에 유리하다.
- 자주 쓰는 상태/공정/마스터 제외 조건에 인덱스가 있다.
- WAL checkpoint로 WAL 파일의 무제한 성장을 억제한다.
- 시작 때 전체 마스터를 반복 저장하던 병목을 제거했다.
- 매일 KCC/심텍 조건 마스터와 설정 ZIP 백업을 만든다.

### 아직 남는 운영 과제

1. 작업 DB 이력은 자동 삭제하지 않는다. 품질 추적을 위해 의도적으로 보존한다.
2. 작업일보 Excel은 행 수가 수만~수십만 행이 되면 열기/저장 시간이 증가한다.
3. 매일 백업 ZIP은 자동 삭제하지 않으므로 장기간 뒤 디스크 사용량을 점검해야 한다.
4. 권장 운영은 연 1회 전체 data ZIP 백업 후 작업일보를 연도별 새 파일로 교체하는 방식이다.
5. DB 파일이 수백 MB 이상이 되면 먼저 전체 백업 후 VACUUM/연도별 보관 정책을 별도 승인받아 적용한다. 자동 삭제나 자동 VACUUM은 현장 이력을 임의 변경할 수 있어 이번 버전에 넣지 않았다.

## 13. 현재 배포 전 필수 설정

현재 V4-1 설정 상태를 기준으로 아래를 확인해야 한다.

- 작업일보: 현재 개발 PC 바탕화면 XLSM 경로. 현장 네트워크 작업일보로 변경 필요.
- 전송 폴더: 현재 바탕화면 DNC 폴더. 실제 설비 전송 폴더인지 확인 필요.
- TLB 원본 DNC 폴더: 비어 있음.
- KCC HDI 원본 DNC 폴더: 비어 있음.
- TLB 조건 시트: 비어 있음.
- KCC HDI 조건 시트: 비어 있음.
- 심텍 HDI 원본: 개발용 바탕화면 경로이므로 현장 경로 확인 필요.
- KCC PKG 원본: 현재 D드라이브 개발 경로이므로 현장 경로 확인 필요.
- 관리 비밀번호 기본값이 `1`이므로 현장 배포 전에 변경 권장.
- 마스터 PC명/IP 허용 범위가 실제 현장 PC와 맞는지 확인.

경로가 비어 있거나 틀리면 V4-1은 해당 공정 DNC를 실행하지 않는다. 이것이 의도한 안전 동작이다.

## 14. 남은 구조적 위험

1. 조건 시트를 `data_only=True`로 읽기 때문에 수식 파일은 마지막으로 Excel에서 계산/저장된 값이 기준이다. 수식 변경 후 저장하지 않으면 캐시 값이 오래될 수 있다.
2. 전송 폴더는 설비 한 대/PC 한 대 전용이어야 한다. 다른 PC가 같은 전송 폴더를 직접 조작하면 Windows 로컬 mutex로 막을 수 없다.
3. 네트워크 SMB 서버의 원자 rename 동작은 서버 구현에 영향을 받는다. 같은 폴더 임시 저장/교체로 위험을 최소화했지만 네트워크 단절 자체는 막을 수 없다.
4. 작업자가 품질 팝업에서 실제 확인 없이 `예`를 누르는 행위는 프로그램만으로 완전히 막을 수 없다. 조장명, 축 비교, 마스터 제외, 로그로 책임 추적성을 높인 상태다.
5. 심텍 SPS는 아직 미구현이다. 탭을 보고 사용할 수 있는 공정으로 오해하면 안 된다.

## 15. 현장 사용 권고 순서

1. V4-1을 검증 PC에서 실행한다.
2. 설정에서 실제 작업일보/원본 DNC/전송 폴더/조건 시트를 지정한다.
3. 전체 data 백업을 한 번 만든다.
4. 각 공정 더미 또는 검증용 LOT로 조건 조회만 시험한다.
5. DNC 파일 복사/설비 수신/자동 삭제를 시험한다.
6. 작업일보 반영과 DNC_LOG_ID를 확인한다.
7. NG 시험을 한 번 수행해 마스터 미등록과 빨간 표시를 확인한다.
8. 2LOT 동일 LOT/서로 다른 조건 차단을 확인한다.
9. 근무 전환 경계와 숨은 팝업을 확인한다.
10. 현장 합격 후 기존 버전을 종료하고 V4-1만 사용한다.

## 16. 롤백

- V4-1에 문제가 있으면 V4-1을 종료한 뒤 기존 V4 또는 현장 사용 중인 V2/V3를 실행한다.
- V4-1 데이터는 `data_v4_1`에만 있으므로 기존 `data`, `data_v4`를 덮어쓰지 않는다.
- 단, 작업일보와 DNC 전송 폴더는 설정상 같은 외부 파일/폴더일 수 있으므로 두 버전을 동시에 사용하면 안 된다. V4-1의 이중 mutex가 같은 PC의 중복 실행을 막는다.
- V4-1 최초 실행 전 데이터는 `data_v4_1/backup/..._before_migration`에 보존되어 있다.

## 17. 개선 효과 요약

- 잘못된 경로/중복 조건/부분 복사에서 실행하지 않는 fail-closed 구조.
- DNC 삭제 성공 전 완료하지 않는 설비 상태 확인 구조.
- 품질 NG를 마스터에 올리지 않고 작업일보까지 일관되게 표시.
- 오등록 마스터를 로그 ID 단위로 제외하고 정상 재검증 가능.
- 근무 전환과 백그라운드 UI 작업의 간헐 오류 감소.
- DB/설정/Excel 손상 시 복구 가능성 향상.
- DB 장기 누적 시 마스터 동기화 성능 향상.
- V1~V4와 V4-1의 동시 실행에 따른 전송 충돌 방지.

V4-1은 기존 V4보다 현장 오류와 불량 방지 측면에서 분명히 강화되었다. 최종 본 적용 판단은 12장의 실제 설비 시험 결과를 기준으로 해야 한다.
