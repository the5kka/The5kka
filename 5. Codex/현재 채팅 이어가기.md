# Codex 채팅 이어가기 기록

## 이 폴더의 목적

이 폴더는 실행파일, DNC 원본, 업무 자료를 옮기는 곳이 아니다.

목적은 Codex 앱/계정/로컬 계정이 바뀌어도 이전 채팅에서 진행했던 프로젝트 맥락을 이어가기 위한 기록용이다.

## 실제 DNC 프로젝트 위치

DNC 프로그램 개발, data, exe, 빌드 파일은 아래 위치에서 계속 이어간다.

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager
```

주요 기준:

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\main.py
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\data
D:\QC\8. Codex\2. JIIN_DNC_Manager\JIIN_DNC_Manager_V2.exe
```

## 현재 계정 상황

- 현재 Codex 작업은 QC 로컬 계정에서 진행 중이다.
- 오국진 로컬 계정의 Codex 앱이 다시 정상 동작하면, 이 기록을 보고 이어가면 된다.
- 오국진 계정 바탕화면에도 `Codex 업무 기준`, `DNC 프로그램 개발 폴더`, `오국진 사용자 폴더` 바로가기를 만들어두었다.

## 지금까지 확인한 내용

- `D:\QC\8. Codex`가 기존 Codex 작업 보관 기준 폴더다.
- `D:\QC\8. Codex\2. JIIN_DNC_Manager`에 DNC 프로그램 최신 작업본과 실행파일이 있다.
- `program_files\main.py`는 2026-06-08 기준 최신 소스 파일로 보인다.
- `program_files` 안에 여러 Codex 백업 파일이 남아 있다.
- 실제 DNC 실행파일/data는 이 폴더로 옮기지 않는다.

## 2026-06-19 오국진 계정 복구 후 이어간 내용

- Codex 앱에서 현재 스레드 제목을 `JIIN DNC Manager 이어가기`로 변경했다.
- Codex 앱의 저장 프로젝트 목록은 현재 비어 있었다. 그래서 앱 내부 프로젝트 이동 대상은 확인되지 않았다.
- 실제 이어가기 기준은 계속 아래 경로다.

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager
```

최신 기준 파일:

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\main_v3.py
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\dnc_rules.py
D:\QC\8. Codex\2. JIIN_DNC_Manager\data
D:\QC\8. Codex\2. JIIN_DNC_Manager\JIIN_DNC_Manager_V3.exe
```

확인 사항:

- `JIIN_DNC_Manager_V3.exe`가 2026-06-15 18:03 기준 최신 실행파일로 보인다.
- `main_v3.py`와 `dnc_rules.py` 문법 검사는 통과했다.
- 단, 소스로 실행하면 `program_files\data`를 쓰고, EXE로 실행하면 상위 `data`를 쓴다. 이 차이 때문에 테스트/현장 데이터가 갈라질 수 있다.
- 실제 현장 로그와 설정은 상위 `D:\QC\8. Codex\2. JIIN_DNC_Manager\data` 쪽을 기준으로 봐야 한다.

우선 리뷰 결과:

1. `dnc_rules.py`에서 원본 DNC 폴더까지 자동 생성하는 부분이 위험하다. 원본 폴더는 존재 확인만 하고, 전송 폴더만 생성 허용해야 한다.
2. EXE 실행 데이터 경로와 Python 소스 실행 데이터 경로가 달라서 검증 혼선이 생긴다. 개발/현장 기준을 통일하거나 명시적으로 분리해야 한다.
3. KCC HDI 조건 시트 조회가 TLB 조건 시트 파서를 그대로 재사용한다. `error_20260615.log`에 KCC HDI 조건 시트 조회 실패가 반복되어 있으므로, KCC HDI 전용 컬럼 매핑/시트명 처리가 필요하다.
4. 실제 EXE 기준 `data\config.json`에서 KCC PKG/TLB 원본 DNC 폴더와 DNC 전송 폴더가 현재 계정 기준으로 존재하지 않았고, TLB 조건 시트는 접근 거부가 났다.
5. 마스터/조건마스터/라이선스 비밀번호 기본값이 `1`이고 평문 저장이라 현장 보호 수준이 낮다.

다른 PC 또는 다른 계정에서 다음 Codex에게 말할 내용:

```text
D:\QC\8. Codex\5. Codex\현재 채팅 이어가기.md 를 먼저 읽고,
D:\QC\8. Codex\2. JIIN_DNC_Manager 를 기준으로 JIIN DNC Manager 프로젝트를 이어가줘.
최신 소스는 program_files\main_v3.py, 최신 실행파일은 JIIN_DNC_Manager_V3.exe야.
먼저 리뷰 결과 1번부터 고쳐줘. 원본 DNC 폴더는 자동 생성하지 말고 존재/접근만 검증하고, 전송 폴더만 생성 허용해줘.
실제 현장 data/config/log는 D:\QC\8. Codex\2. JIIN_DNC_Manager\data 기준으로 봐줘.
```

## 2026-06-19 사용자 추가 전달: 프로젝트별 이어가기 기준

### 1. DNC V3 프로젝트

DNC V3 프로젝트를 이어서 진행한다.

기준 폴더:

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager
```

중요 기준:

- V2는 절대 건드리지 않는다.
- V3 핵심 파일은 `program_files\main_v3.py`다.
- V3 실행 파일은 `JIIN_DNC_Manager_V3.exe`다.
- PyInstaller spec은 `program_files\JIIN_DNC_Manager_V3.spec`다.
- 현재 D드라이브 프로젝트와 `C:\Users\오국진\Documents\QC 백업 Data\QC\8. Codex\2. JIIN_DNC_Manager` 백업은 174개 파일 전체 해시가 동일하다고 사용자가 확인했다.
- 작업일보 현재 설정은 `C:\Users\QC\Desktop\타사 DNC 작업일보.xlsm`이다.
- KCC_PKG, TLB_HDI, 지그 일원화 자료는 QC와 오국진 바탕화면 양쪽에 동일하게 있다.
- `config.json`은 정상 UTF-8 JSON이고 사용자 경로가 QC/오국진으로 섞여 있다.
- `data` 폴더는 공정별로 분리되어 있다.

```text
data\KCC_PKG
data\TLB
data\KCC_HDI
```

V3 내용:

- KCC HDI를 TLB 방식 기반으로 추가했다.
- KCC HDI 화면은 Tool No 대신 관리번호로 표시한다.
- KCC HDI는 KCC PKG와 같은 KCC 로고를 사용한다.
- 작업일보는 `타사 DNC 작업일보.xlsm`을 사용한다.
- 작업일보 시트명은 `KCC HDI`다.

DNC V3 작업을 시작할 때 먼저 읽을 파일:

```text
D:\QC\8. Codex\2. JIIN_DNC_Manager\PROJECT_RULE.md
D:\QC\8. Codex\2. JIIN_DNC_Manager\data\config.json
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\main_v3.py
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\dnc_rules.py
D:\QC\8. Codex\2. JIIN_DNC_Manager\program_files\JIIN_DNC_Manager_V3.spec
```

### 2. OJT 인증 시험 프로젝트

시험문제 생성 프로젝트를 이어서 진행한다.

목적:

- 사용자가 제공하는 자료, 시험 범위, 과목, 단원 기준으로 시험문제를 생성한다.
- 단순 암기식보다 실제 시험에 나올 만한 문제 형태로 구성한다.
- 필요 시 정답과 해설을 포함한다.
- 객관식, OX, 단답형, 서술형, 실무형 문제 생성이 가능하다.
- 사용자가 원하는 문항 수, 난이도, 형식에 맞춘다.
- 필요하면 한글 문서, Word, Excel, PPT 형태로 정리한다.

진행 방식:

1. 사용자가 자료 파일이나 시험 범위를 제공하면 먼저 내용을 읽고 핵심 개념을 정리한다.
2. 문항 수, 난이도, 문제 유형, 정답/해설 포함 여부를 확인한다.
3. 문제를 생성한다.
4. 정답 및 해설을 생성한다.
5. 필요하면 출력용 문서 형태로 정리한다.

새 OJT 시험 작업을 시작할 때는 과목, 범위, 난이도, 문항 수, 문제 유형을 먼저 확인한다.
